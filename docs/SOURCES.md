# Sources and data limits

Research checked on 2026-09-21. These sources establish the implementation approach. Automated tests use synthetic X responses and do not log into real accounts.

- [X Help: How to change your country settings](https://help.x.com/en/managing-your-account/how-to-change-country-settings): “About this Account” is public for public accounts, inferred from aggregated IP addresses, and may display a country or a broader region. It is distinct from an optional profile location and the private account country setting. The extension displays the reported country/region, not nationality or a post's physical origin.
- [X API v2: Get Users by Username](https://docs.x.com/x-api/users/get-user-by-username): the documented `user.fields` options do not include `about_profile` or `account_based_in`. The extension therefore cannot obtain this particular value from the documented user lookup interface.
- [RhysSullivan's page-context request implementation](https://github.com/RhysSullivan/twitter-account-location-in-username/blob/main/pageScript.js): independently inspected code confirms a GET to `/i/api/graphql/XRqGa7EeokUU5kppkh13EA/AboutAccountQuery`, with `variables={"screenName":"handle"}`, and country value at `data.user_result_by_screen_name.result.about_profile.account_based_in`.
- [X-Posed's API client](https://github.com/xaitax/x-account-location-device/blob/main/extension/src/background/api-client.js) and [constants](https://github.com/xaitax/x-account-location-device/blob/main/extension/src/shared/constants.js): corroborate the operation ID, use of a signed-in session with authorization and CSRF headers, response path, and optional `core.screen_name` identity check.

The extension's background worker observes a small header allowlist on successful X GraphQL requests using Chromium's `webRequest` API. Credentials stay in extension memory, scoped to their exact HTTPS origin. They never enter storage, content scripts, page messages, logs, or third-party requests. The extension does not wrap page network APIs or inject MAIN-world code. It does not include a hard-coded bearer credential, infer a country from names/language/bios, or perform account blocks/mutes.

The operation ID above is fixed in the extension and source-reviewed, not a guaranteed current API contract. A change to X's operation ID requires an extension update. Requests use that fixed AboutAccountQuery endpoint on the authenticated origin, reject redirects, validate the returned account identity, and return only country/status data to content scripts. No code is downloaded or executed, script bundles are not scanned, and rejected requests are not retried indefinitely.

Lookups share pacing, deduplication, and rate-limit cooldowns across tabs. Turning off the extension or automatic lookups stops header observation, aborts active lookups, and clears in-memory authentication. Browser restarts and worker suspension also discard credentials; a normal successful X request is needed to learn them again. Settings and a bounded, expiring country cache remain in local browser storage.

X can change its private request requirements, endpoint identifiers, response structure, and page markup. A working signed-in session may still receive a challenge or rejection. Missing values remain unknown and network/authentication failures remain unavailable. Pending authors are hidden by default while a filter is active until a location is available; this can be disabled in the popup. An empty Hide selected list does not hide pending authors. Confirmed unknown locations use the separate Hide unknown setting. Filtering applies to the outer post's author, not the author of an embedded quote. The displayed country/region is X's estimate, not nationality or a post's physical origin.
